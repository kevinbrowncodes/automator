# automator

Everything macOS Automator on my Mac: Quick Actions, standalone workflows,
Automator applications, and the shell scripts they call.

## Layout

| Folder | What lives here | Where macOS expects it |
|---|---|---|
| `quick-actions/` | `.workflow` bundles that appear in Finder's Quick Actions / Services menu | `~/Library/Services/` |
| `workflows/` | Standalone `.workflow` files you open and run from Automator | anywhere |
| `applications/` | Automator `.app` bundles (double-click or drop files on them) | anywhere |
| `folder-actions/` | Folder Action workflows (none yet) | `~/Library/Workflows/Applications/Folder Actions/` |
| `scripts/` | Scripts referenced by the above | `contact_sheet.py` is copied to `~/Library/Application Support/automator/`; the rest run from wherever they're called |
| `tests/` | Tests for the scripts (run by the `contact-sheet` gate) | n/a |
| `gates/` | Checks that block a push when a rule is broken (run by `hooks/pre-push`) | n/a |

Automator documents are bundles: a `.workflow` or `.app` is a folder, and the
real content is `Contents/document.wflow` (an XML plist). That file is what
`git diff` shows you. The `QuickLook/` PNGs inside bundles are regenerated by
Automator on every save, so expect them to churn.

## Day to day

**Install the Quick Actions on a new Mac**

```sh
./install.sh
```

Copies everything in `quick-actions/` into `~/Library/Services/`, copies the
scripts they call into `~/Library/Application Support/automator/`, marks each
Quick Action visible in Finder's context menu, and restarts Finder. Safe to re-run.
After editing `scripts/contact_sheet.py`, re-run it so the action picks up the change.

**After editing a Quick Action in Automator**

Automator saves Quick Actions straight to `~/Library/Services/`, not to this
repo. Pull the change back, then commit:

```sh
./pull.sh          # refresh the ones tracked here
./pull.sh --all    # also grab any new ones on this Mac
git diff           # sanity-check
```

**Workflows and apps** are not installed anywhere. Open them from this repo
directly, or edit them in Automator and save back into the same folder.

## Inventory

### Quick Actions

- **Claude - ask**, **Claude - codeHere**, **Claude - send**: installed by the
  Claude desktop app. Selected text, folder, or files go to Claude via the
  `claude://` URL scheme.
- **Contact Sheet**: for each selected video, writes `<name>.contact.jpg` next to
  it and opens it in Preview. Top: a frame every 0.5 s in 6 columns of ~448 px
  tiles, each stamped with its time (`0:12.5`). Bottom, under "Seams": the frames
  0.1 s before and 0.3 s after each 10 s mark, side by side, to spot a jump where
  two 10-second shots were joined (none if the video is too short to have one).
  No dialog: one click. A thin wrapper around `scripts/contact_sheet.py`, which
  grabs each frame with its own `ffmpeg -ss <t> -i` call (never the select/fps
  filters, which can fake a frozen hold) and lays the sheet out with Pillow,
  since Homebrew's ffmpeg has no drawtext. About 3 s for a 30 s 1344x768 take.
  Problems (not a video, ffmpeg error) show as notifications. Needs Homebrew
  `ffmpeg` and `python3` with Pillow.
- **Crop to Square**: center-crops the selected images to a 1:1 square and writes
  `<name>-square.<ext>` next to each original. Originals are untouched. Built on
  the `sips` tool that ships with macOS, so there is nothing to install.
- **Crop to Vertical**: same idea, but center-crops to a 9:16 portrait frame
  (Shorts / Reels / TikTok) and writes `<name>-vertical.<ext>`.
- **Extract Last Frame**: saves the last frame of a movie as `<name>_lastframe.png`
  next to it. Needs Homebrew `ffmpeg`.
- **Open in Visual Studio Code**: opens the selection in a new VS Code window.

### Workflows

- **Combine Excel Workbooks**: starts from `~/Desktop/INBOX`.
- **Create New File**: prompts for a filename and touches it in the front Finder window.
- **Minmize All Windows**: hides every app except Finder and collapses Finder windows.
- **Text > Wrap in Quotes**: wraps the input text in double quotes.

### Applications

- **new app / board / chat / code / devonthink / file / NLM / note / path / web**:
  one-click launchers. `new chat` shows a picker for the AI chat apps;
  `new file` asks which Finder window gets a new `Untitled.txt`.
- **AudioLDM Transfer**: drop audio files on it to regenerate them with AudioLDM.
  Calls `scripts/audioldm_transfer.sh`.
- **AutomateCamp1**: runs the published AutomateCamp .NET build.
- **Create Blank Text File**: makes a new file in the front Finder window.
- **Move**: Move Finder Items with no destination set.

## Things that are pinned to this Mac

These reference paths outside the repo and will need editing on another machine:

- `AudioLDM Transfer.app` calls the script at its **old iCloud location**
  (`~/Library/Mobile Documents/com~apple~Automator/Documents/Scripts/`), not
  the copy in `scripts/`. The script itself activates a venv at `~/venvs/audiosr`.
- `AutomateCamp1.app` runs a binary on the external volume `Macintosh ED`.
- `Extract Last Frame` hardcodes `/opt/homebrew/bin/ffmpeg`.
- `Contact Sheet` hardcodes `/opt/homebrew/bin/{ffmpeg,ffprobe,python3}`, and needs
  Pillow in that Python (`python3 -m pip install --break-system-packages Pillow`).
  If a Homebrew Python upgrade loses Pillow, the action says so in a notification.

## The gotcha that will bite you

Copying a `.workflow` into `~/Library/Services/` is **not enough** to make it
appear under right-click > Quick Actions. Two separate things have to happen:

1. The system registers the bundle. A file copy does this on its own.
2. The service is marked visible in the context menu, via an entry in the `pbs`
   preference domain under `NSServicesStatus`.

Automator writes that second entry for you when *you* save a Quick Action. A
plain file copy does not, so the action registers but stays invisible, with no
error and nothing to click. It also does not show up under the Customize item
in that submenu, because that panel lists app extensions, not Automator actions.

`install.sh` writes the entry for every Quick Action it installs, which is why
you should install with the script rather than dragging bundles into
`~/Library/Services/` by hand.

There is a second, quieter way to vanish: a Quick Action set to receive **no
input**. Finder only lists actions in the right-click menu if they take
something (files, folders, images, text), so a no-input action lands only under
Finder > Services in the menu bar. `gates/quick-actions-take-input.sh` fails the
push if any action here receives nothing; `install.sh` turns the hook on.

No Quick Action can appear when you right-click **empty space** in a folder:
that click clears Finder's selection, so there is nothing to pass and Finder
leaves the Quick Actions section out of the menu. Something that should work on
"the current folder" from empty space needs a Finder Sync extension instead, as
in `kevinbrowncodes/finder-new-file`.

Finder also builds this menu once at launch, so it needs a restart after any
change. `install.sh` does that too.

To check on a service by hand:

```sh
defaults read pbs NSServicesStatus            # is it listed and ContextMenu = 1?
/System/Library/CoreServices/pbs -dump_pboard | grep 'Your Action'
```

## Gates

`hooks/pre-push` runs every `gates/*.sh`; `install.sh` turns the hook on.

- `quick-actions-take-input`: every Quick Action receives input (see "The gotcha" above).
- `contact-sheet`: `tests/test_contact_sheet.py` passes with at least 95% line
  coverage of `scripts/contact_sheet.py`. Needs `coverage` in Homebrew Python.
- `no-select-filter-frames`: nothing extracts frames with ffmpeg's `select=` or
  `fps=` filters.

## Things git cannot carry

- Custom Finder icons on `.app` bundles live in a resource fork on an `Icon\r`
  marker file. Git ignores it, so re-apply custom icons by hand after a fresh clone.

## Source of truth

The originals still exist in `~/Library/Services/` and in iCloud Drive under
`Automator/`. Nothing there was moved or deleted. Going forward, this repo is
the copy to trust.
